# 1.1 How computers work — Day 4: GPUs and the three regimes
Date: 2026-11-27

## Three things that limit speed (Horace He)
1. Compute: time spent doing FLOPs (matmuls on tensor cores).
2. Memory bandwidth: time spent moving data between GPU memory (HBM/DRAM)
   and the compute units. Elementwise ops (add, relu, cos) live here.
3. Overhead: everything else — Python interpreter, framework dispatch,
   kernel launches. GPU sits idle waiting for the CPU.
Fix depends on the regime: bigger/fused ops for bandwidth, fewer small ops
(batching, CUDA graphs, compilation) for overhead.

## Arithmetic intensity
FLOPs per byte moved. Matmul of n×n: ~2n³ FLOPs over ~3n² values -> high, so
compute-bound. Elementwise op: ~1 FLOP per element read+written -> low, so
memory-bound. Operator fusion = do several elementwise ops in one pass over
memory instead of one pass each.

## GPU programming model (CUDA)
- Kernel: a function run by many threads in parallel.
- Thread -> block (threads that can share fast on-chip shared memory and
  synchronise) -> grid (all blocks of one kernel launch).
- Warp: 32 threads that execute the same instruction together (SIMT);
  branches that split a warp run both paths serially.
- Memory: registers (per thread) > shared memory (per block, on chip)
  > global memory (HBM, large and slow relative to compute).

Same lesson as CPU caches: moving data costs more than computing on it.
